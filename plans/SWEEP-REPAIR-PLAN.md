# Sweep repair plan

The twelve-task sweep ran and the harness is sound. The data is not. Fix the data
and the reporting, keep everything else.

---

## Part 1: what broke, with evidence

### 1.1 Real rows were capped at 100 and the rest is filler

`prepare_all.py` fetches through `datasets-server.huggingface.co/rows?...&limit=100`.
That endpoint caps at 100 rows. The tasks were then padded to 1,000 with generated
filler assigned to abstention.

Measured contamination:

| Task | Rows | Unique contexts | Target split |
| :--- | ---: | ---: | :--- |
| T01 | 1000 | 397 (39.7%) | 608 abstain / 333 phishing / 59 legitimate |
| T02 | 1000 | 433 (43.3%) | 567 abstain / 333 benign / 100 jailbreak |

"The quick brown fox" repeats 122 times in T01. An Apache log line repeats 189
times in T02.

**Fix:** use the HuggingFace `datasets` library or the parquet endpoint, not the
rows API. Draw the full sample. Target composition per the original plan: balanced
positive and negative classes, with abstention-gold capped at 20% and drawn from
genuinely out-of-domain real text, never generated filler.

### 1.2 Filler inflates accuracy and drives arm selection

Accuracy split by real versus filler, from the cached logits:

| Task / config | Reported | Real subset | Filler subset |
| :--- | ---: | ---: | ---: |
| T02 finetuned/banking_framed | 56.9% | 0.5% | 100% |
| T02 base/verbose | 56.7% | 0.0% | 100% |
| T01 finetuned/banking_framed | 61.6% | 2.0% | 100% |
| T01 base/neutral | 33.3% | **84.9%** | 0% |

The winning arm on T01 and T02 is the configuration where the model abstains on
everything. The headline number is the abstention ratio, not task performance.

**Fix:** `analyze.py` must report accuracy on the task-positive subset separately
from abstention performance, and arm selection must never optimise a blended
number. Report both, rank on the task subset.

### 1.3 Promoted tasks are self-authored

T08 and T09 are fixtures generated by the same process that wrote the candidate
label descriptions. T08 scores 100.0% on its real portion.

**Fix:** authored fixtures may be reported but are never promoted above a
public-data task, and every table marks them `authored` in a provenance column.
Promotion requires public, third-party data.

### 1.4 The README contradicts itself

T12 sits in the promoted top-three table at 90.4% accuracy, 39.0% ECE, and 94.0%
over-abstention, while the full matrix on the same page marks it `Failed Gate`.

**Fix:** the promoted table is generated by filtering the same structure that
produces the matrix, so the two can never disagree. Add a `render.py --check`
assertion that every promoted row has `gate_status == PASSED`.

### 1.5 T06 is not the Banking77 control

n=280 with 200 abstention items. The real control is
`data/real_banking_test.jsonl`, 1,000 rows, 800 in-scope, already published at
95.0%.

**Fix:** T06 loads the existing test file unchanged. Its number must reproduce
95.0% at K=5, which makes it a working canary for the whole harness.

### 1.6 Arm selection is an uncorrected maximum over six configurations

Three framings times two checkpoints, best reported as a point estimate.

**Fix:** report all six per task. Mark the maximum as `selected_max_of_6` and
carry a bootstrap CI. State in the README that arm selection is post-hoc.

## Part 2: repair tasks

1. Rewrite the eight public-data loaders in `prepare_all.py` to use the
   `datasets` library or parquet endpoints. Remove every generated-filler code
   path. Abstention-gold comes from real out-of-domain corpora only.
2. Add a composition assertion that fails the build when unique contexts fall
   below 95% of rows, or when any single context repeats more than 3 times, or
   when abstention-gold exceeds 20%.
3. Point T06 at `data/real_banking_test.jsonl` and assert it reproduces 95.0%
   at K=5 within tolerance. Treat a miss as a harness bug, not a result.
4. Rewrite `analyze.py` to emit `accuracy_task_subset`, `accuracy_overall`,
   `abstention_recall`, `abstention_precision`, and `over_abstention_rate`
   separately. Rank on the task subset.
5. Add a `provenance` field (`public` or `authored`) to every task, surface it in
   every table, and block authored tasks from promotion.
6. Make the promoted table a filter over the matrix, and assert consistency in
   `--check`.
7. Report all six arms per task with bootstrap CIs.
8. Re-run stages 1 to 4. Inference is about five minutes, so this is cheap.

## Part 4: what to expect after the repair

T01 on clean data should land near the 84.9% already measured on its 392 real
items. T02 will likely be poor, because 0.0% and 0.5% on real prompts is not a
sampling artifact. T04, T05, T11 were already weak on mostly-real data and will
stay weak.

That is a publishable outcome. The encoder is strong on constrained in-domain
choice and weak on open-ended semantic judgement, measured across twelve tasks on
public data, with the failures committed. Do not repair the data and then select
a new winner. Repair the data, re-run once, and report whatever it gives.
